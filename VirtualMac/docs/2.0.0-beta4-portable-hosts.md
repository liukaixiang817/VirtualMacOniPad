# Beta4: experimental portable hosts and crash feedback

Build 1004 removes the single `iPad14,6 / 20B101` admission rule from the independent macOS 27 App, CPU provider, counter reader, capability query and IPA query. The complete macOS 13 and macOS 27 choices remain separate; there is no silent mixture or fallback.

## Scope

- Target hardware: M1/M2 iPads and A16 iPhone 14 Pro / 14 Pro Max.
- Experimental system range: Dopamine on iOS/iPadOS 15 through 16.3.1. Hardware must actually support the selected system and jailbreak; this does not make an impossible downgrade possible. The 2024 M2 iPad Air cannot run this system range.
- iOS 14 and other jailbreaks are outside this Dopamine release.
- Actual device acceptance is on an M2 iPad running iPadOS 16.1.1 (20B101). Other models/builds are experimental, not verified working combinations.

The App's 41 source objects are compiled for iOS 15, including restored compiler availability checks for system APIs. The six local UIKit input declarations now permit iOS 15. The independent runtime's 146 Mach-O images have an iOS 15 loader minimum and new signatures; this header adjustment alone does not prove that every host export exists on every system. Native context offsets and trap operations are unchanged. Actual context version `0x206879700000000e`, valid mapped ranges, ownership, signatures and capability results are still required. A mismatching context must fail rather than be used with guessed offsets.

## What to send after a failure

1. Reopen VirtualMac after the crash. Do not delete the App or clear its files first.
2. Open Settings → Export Diagnostics, then save the ZIP to Files. The error-details screen also has Save Diagnostics to Files.
3. Send the ZIP with the device model, iOS/iPadOS version/build, Dopamine version, selected backend, and the last action before the failure. Say whether the App closed, the guest stopped, or the device rebooted.
4. The App’s Create GitHub Issue button opens https://github.com/liukaixiang817/VirtualMacOniPad/issues/new. Review the archive before posting publicly: logs can contain VM names, paths and network details. Nothing is uploaded automatically.

The ZIP includes the independent backend's current log, a bounded previous-launch log, persistent launch history, installation metadata, and the newest matching VirtualMac/VMM/GPU crash reports. Crash collection is capped at 12 reports, 8 MiB per report and 32 MiB in total. Unrelated application crash reports and full-device jetsam reports are excluded. An App that fails before reaching `main` cannot write a new launch record; its system crash report remains the useful evidence.

## Cursor refresh change

Cursor publications now wake the existing 60/120 Hz display scheduler, including when no new full framebuffer arrives. The idle stop, guest cursor ownership and original two-finger axes are unchanged. A prior real guest cursor movement test on the same source change recorded 1,108 display callback intervals: median 8.337 ms, p95 8.479 ms, maximum 8.758 ms, with one full framebuffer update. This measures callback cadence, not physical 120 fps or end-to-end input latency. It does not establish that all intermittent stutters are fixed.

## Remaining limitations

Cross-model/cross-version boot acceptance, complete host-symbol audits for older systems, occasional GUI stutter and missing icons remain open. Restore-image installation, microphone capture, Bluetooth, bridged/guest-IPv6 networking and advanced GPU features remain deferred. Existing VM bundles are supported by this package; clean creation of a new guest from an IPSW is not promised. Audio remains independent of Bluetooth.
