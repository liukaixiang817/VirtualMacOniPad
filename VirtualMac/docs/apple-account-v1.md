首次运行时可直接在 macOS 设置助理中输入 Apple 账户。Apple 双重认证仍由
Apple 正常完成，应用不保存账户密码或验证码。

## 创建和启动链路

1. 从实际 IPSW ZIP64 归档读取 `BuildManifest.plist`，核对恢复 Build。
2. 在持久化安装目录生成 Henge v2 规则的身份，并先保存对应网络设置。
3. 原生恢复程序生成真正的 `HardwareModel`、`MachineIdentifier`；在启动
   `VZMacOSInstaller` 前，将它们的 SHA-256 绑定到身份文件。
4. 恢复结束后，将身份、选项与安装结果一起原子移动到最终 VM bundle。
5. 每次冷启动核对 profile UUID、原生身份、固定 MAC 和重复身份，写入该次
   启动的私有 handoff。原生 CPU provider 只为通过这些校验的来宾启用策略。

每台 VM 的 `AppleAccountIdentity.plist` 保存合成序列号、MLB、模型和四个 MAC，
每次启动沿用同一份数据。真正的原生 ECID、硬件模型二进制和 ARM 驱动选择
信息保留。此实现不需要真实 Mac 的身份捐赠。

## 原生运行时

`VirtualMac/vz/apple-account/VMAppleAccountRuntimeV1.c` 接入实际 Hypervisor
退出和寄存器回填路径，处理 VMApple 配置 MMIO 中的序列号、模型和网络身份。
在经过验证的 CPU 所有权范围内，检查早期 PC、页表和设备树，补入根节点 MLB。

原生 ARM64 sysctl stub 只对清单中的账户服务及设置助理返回兼容值；未知
进程、驱动和内核调用仍保持真实 VM 结果。注入位置位于审核后的内核
`__text` 零填充区域，并与真实代码共享可执行页面。运行时同时跟踪原生
map/unmap/protect/remap 和主核 reset，覆盖恢复环境切换与来宾热重启。

27.2 的实机探针还发现，早期内核新增的 `MRS ID_AA64ISAR3_EL1` 在原后端
触发未定义指令 panic。运行时补充了这一架构 ID 寄存器的 AArch64 EL1
只读处理，返回当前虚拟 CPU 不提供新扩展的值 `0`；仍通过既有所有权校验
提交目标寄存器和 PC。写入、其他寄存器和其他执行级别保持原有异常路径。
修复后，同一台新建 27.2 已在 iPad 进入首次设置。该寄存器编码参考
[Arm Trusted Firmware](https://github.com/ARM-software/arm-trusted-firmware/blob/master/include/arch/aarch64/arch.h)。

已审核内核为 `24G90`、`25G83`、`26A5416b`、`26B123`、`26B131`。`26B131` 的真实 Apple 恢复镜像内核已核对，相关 `__text` 与 `26B123` 字节一致。
其他有效 Build 同样会生成身份和安装选项；未知内核不使用猜测的函数、进程字段或注入偏移，Apple 服务可用性仍需实测。旧后端不提供这套运行时；
已有身份的 VM 选用旧后端时会提示切换到完整 27 后端。

账户 VM 禁止修改其固定 MAC，关闭休眠到磁盘；正常暂停和继续仍使用既有路径。
身份丢失、原生绑定变化或库内重复 UUID 会拒绝启动，避免悄悄换一套身份。

## 构建与验证

按顺序使用 `VirtualMac/scripts/development/` 中以下脚本；各脚本的 `--help`
列出输入。正式构建使用 `assemble-apple-account-product-v1.py --release`，以已发布的 Beta 7 App 和通过实机账户验收的 CPU provider 为基线。

1. `build-apple-account-stubs-v1.py` 生成两种进程布局的 ARM64 stub。
2. `build-apple-account-installer-v1.py` 构建三个独立恢复组件。
3. `build-apple-account-runtime-v1.py` 重建实际 CPU provider。
4. `assemble-apple-account-product-v1.py` 更新签名、运行时 manifest、依赖证明
   和 App 内锚点，并明确重编译实际主程序和库界面对象。
5. `package-independent27-apple-account-v1.py` 以已验证包为基线打包，保留
   无线、音频、相机及原恢复栈，并逐文件验证提取结果。

1000 组生成身份已用实际 OpenCore/macserial 独立校验。两种进程布局各通过
3472 个原生 stub 用例。CPU provider 可从标准脚本逐字节复建；完整产品的
原生代码相同，但依赖证明包含输入路径，所以换输出目录会改变 manifest、
App 锚点及最终文件哈希。见 `canonical-rebuild-verification-v2.json`。

新增的 ID 寄存器处理另通过 16,513 个原生测试，覆盖所有目标寄存器、
执行级别、NZCV 组合，以及写请求和相邻寄存器的拒绝行为。

三个新的恢复组件使用独立文件名，原 `1.2.4` 恢复栈保持原样。App 固定校验
组件哈希、所有者和权限；安装包依赖该已验证的原恢复栈版本。测试中使用正常
App 安装与启动入口，不通过克隆已登录磁盘替代新建 VM 验收。

## 参考和改写范围

身份算法、设备树解析和原始进程清单来自用户提供的 Henge Build 104 材料。
`reference/` 保留参考 C 源码；原生 Hypervisor 接口、ARM64 stub、安装事务、
ZIP64 BuildManifest 读取以及 App/包集成为本项目实现。

Apple 官方说明的虚拟机 iCloud 条件见
[Using iCloud with macOS virtual machines](https://developer.apple.com/documentation/virtualization/using-icloud-with-macos-virtual-machines)。
本实现的实际支持范围以上述独立实机验收为准。

## Beta 8 正式包

`artifacts/2.0.0beta8/VirtualMac_2.0.0beta8_1008.deb` 包含账户专用恢复组件、正式 App 以及首启和冷启动运行时。新来宾不需要在安装后手动添加账户权限，也不依赖可选 Guest Tools 或 SSH；首次设置助理到达 Apple 账户页面时即可正常登录并完成 Apple 双重认证。每台来宾的身份在恢复前生成并写入其 bundle，后续启动重复读取。

## Beta 9 RC2：新版本与默认身份（2026-11-26）

新建恢复任务在恢复前生成独立 profile UUID、序列号、MLB 和固定 MAC，保存
`AppleAccountIdentityV1`、实际恢复 Build 和休眠设置；恢复生成的原生
`MachineIdentifier` 与 `HardwareModel` 仍由 Apple 创建，随后绑定其哈希。
不再因为 Build 尚未列入内核审核表而静默跳过身份生成。已存在的身份不重新生成。

安装选择器每次打开从 Apple 官方 MESU 目录和 VirtualBuddy 历史目录获取版本，
使用跳过缓存的请求，并提供刷新按钮、下拉刷新和版本号/Build 搜索。新大版本
不再受固定最大版本过滤；推荐的已验证版本和离线目录仍保留。目录中发布了
可用的 Mac IPSW 后，未来版本可出现在“选择其他 macOS 版本”中。此行为不承诺
苹果尚未提供的 IPSW、网络实时性或未经实测的未来系统兼容性。

功能候选包 `1009-1` 在 M2 iPad Pro / iPadOS 16.1.1 上安装，15 个变更组件均完成
哈希读回。用户原有的 `27.2.1 / 26B131` 来宾已补齐遗漏身份并正常冷启动，
日志确认设备树身份和限于账户相关进程的内核策略已实际加载；保留其原生身份
和磁盘，没有重新安装。按用户要求跳过后续 27.2.1 账户认证测试，未宣称 iCloud 已登录。最终 RC2（`1009-2`）另完成实机安装与 15 个组件哈希读回；安装准备、目录、CPU 和触控组件与该功能候选包一致。

另使用实际最终产品安装准备 API，在 iPad 上对元数据合成的未来 Build
`99Z123` 分别传入两种后端选择标记，均生成了独立身份与配置。该夹具不包含
未来操作系统，未执行未来来宾或宣称其云服务通过；测试没有新建虚拟机。
主机回归覆盖真实 Apple `26B131` 目录、合成未来大版本与新 VirtualMac 产品名、
排序、合并和离线回退，以及已知/未来 Build 身份生成和无效 Build 拒绝。
