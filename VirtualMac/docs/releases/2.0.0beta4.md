# 2.0.0beta4 — build 1004

Beta4 removes the development iPad model/build lock, retains the cursor refresh fix, and adds a local crash-feedback workflow.

## Installation and compatibility

Install `VirtualMac_2.0.0beta4_1004.deb` from this repository's Release using your existing Dopamine package manager. Shut down the guest normally and close VirtualMac first. The package upgrades Beta3 in place, keeps disks/settings, and contains both complete backends without requiring 1.2.3. Existing 1.2.3 may coexist.

Experimental targets are M1/M2 iPads and A16 iPhone 14 Pro / Pro Max on **Dopamine, iOS/iPadOS 15–16.3.1**. Only the M2 iPad on 16.1.1 (20B101) has current device testing. Other combinations may reject an unknown native ABI, have missing host APIs, or crash. iOS 14 and other jailbreaks are outside this release. A device must be capable of running the selected OS; for example, 2024 M2 iPad Air models cannot install this range.

This package opens existing VM bundles. Installing a brand-new guest from an IPSW is still deferred. Backend version 27 is distinct from the guest OS version.

## Changes

- Replace the single-machine/build gate in App, CPU, counter, capability and IPA paths with explicit experimental target admission.
- Compile the App for iOS 15; lower runtime loader minimums and regenerate matching GPU process identity data. Keep actual CPU context-version, mapped-memory, signature and ownership checks.
- Keep the display scheduler active for real cursor-only updates. Per-VM 120 Hz remains a requested mode, not a promise of physical 120 fps.
- Include the independent backend log, persistent launch history, previous-launch tail, and up to 12 matching VirtualMac/VMM/GPU crash reports in diagnostics. Exclude other apps' crash reports.

After a crash, reopen VirtualMac and choose **Settings → Export Diagnostics**, then save the ZIP to Files. Send it with the model, OS build, Dopamine version, backend and reproduction steps. The App’s Create GitHub Issue button opens this fork’s issue form. Review paths/network details before posting publicly. No automatic upload occurs. The failure-details screen offers the same export path.

For implementation boundaries and remaining work, see [portable host notes](../2.0.0-beta4-portable-hosts.md). The accompanying `device-validation.json` distinguishes current device tests from inherited feature evidence. Remaining stutters, missing icons, advanced GPU features, microphone/Bluetooth, guest IPv6/bridging and clean guest installation are not claimed fixed.

The release includes the complete deb, App/network source and relink inputs, validation report, README, and SHA-256 checksums. Generated runtime anchors identify this release's signed product; development scripts that reference diagnostic workspaces are historical build recipes rather than a standalone clean build system.
