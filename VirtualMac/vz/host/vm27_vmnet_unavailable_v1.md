This application-private provider implements the unavailable-network contract for the five original macOS27 VZ vmnet imports. The diagnostic backend configuration must use `network=disabled` and zero virtual NICs. This is a loader bridge, not working virtual networking.

`vmnet_copy_shared_interface_list` creates a real retained empty XPC array of interfaces offered by this private backend. This does not assert that the iPad has no physical network interfaces. The original VZ consumer immediately asks for its XPC array count, so an unconditional null enumeration would be unsafe. The actual allocation can fail normally with `ENOMEM`; no fictional object is returned.

The four remaining functions return the documented `VMNET_FAILURE` value 1001. The three nullable constructors/copy operations return null and write exactly one 32-bit failure status when the optional output exists; all four set `errno=ENOTSUP`. Unknown network/configuration/address pointers are never dereferenced. No successful configuration/network object, serialization, port forwarding rule, asynchronous completion or host network operation is produced. Status pointers retain the SDK's valid/aligned/writable caller contract.

The original consumers explicitly check nullable results for configuration creation (RVA `0xee600`), network creation (`0xef0e0`), and serialization (`0x16c2b8`), and compare the port-forwarding result with success 1000 (`0xeef54`). The shared-list call at `0x8f5dc` does not check null before the following `xpc_array_get_count` call. This implementation changes no original consumer instructions or strong import requirements and imports no old macOS13 backend. Its library current/compatibility versions are 1.0.0, matching the original vmnet dependency's minimum. Original VZ loading, error presentation, device execution and full guest boot remain separate unproven steps.
