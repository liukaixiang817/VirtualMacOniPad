# VM27 private client registration

This implements a single selected client's title inventory for the original VMM's actual `xpc_connection_get_pid` → one `pid` matching pair → `LSDisplayName` item query. The identity is an immutable private CFDictionary, passed only from this helper's retained matching CFArray to this helper's item query. It is not a host LSASN and must not be forwarded to system LaunchServices APIs.

The owned service bootstrap configures its expected peer PID, reviewed CDHash and immutable nonzero nonce. The actual native received message contains exactly `privateMethod="VM27.register-client-title.v1"`, `nonce` as UINT64 and `clientDisplayName` as a nonempty UTF8 string of at most 4096 bytes. The recipient compares the native dictionary and native connection audit tokens, actual peer PID/euid, PID version, current kernel CDHash and CS_VALID before committing state. A fabricated local dictionary cannot register. Queries check the saved audit token against the current kernel again, so a reaped peer or recycled PID cannot expose an earlier title. No host daemon, launchd service or global registration is created.

First registration creates one real CF identity/title pair. Repeated equal messages from the identical token are idempotent. Changed title, token, method, nonce or extra fields fail without replacing it. Only session -2, one live pointer pair with real integer CFNumber PID and `pid` CFString key, and this helper's own identity with `LSDisplayName` are supported. Unknown peers return NULL with ENOENT; a dead or invalidated registered peer returns NULL with EACCES. Unsupported inputs fail without claiming a successful global query. Live CF inputs must not be concurrently mutated during a call. Arbitrary invalid CF addresses are not claimed safe.

The next production integration is finite: on the existing owned original-instance control channel, send the actual frontend bundle display name before completing the one-shot bootstrap. Configure the child with the exact parent PID/CD and nonce already used by that reviewed channel. Pass the actual received registration dictionary to `VM27ClientRegistrationReceiveV1`; only after registration and genuine one-shot binding succeed may the original VMM handler receive the peer. This is a new explicit bootstrap message, not a fabricated original application's reply. The frozen existing v7 transport is unchanged; this integration remains pending.

A local own anonymous-XPC parent/child test has exercised real kernel peer credentials, one store, equal retry, five protocol/state failures, twenty concurrent title queries, genuine child wait/absence and stale-token rejection. Separate actual two-process tests with a wrong reviewed CDHash and wrong expected PID each refuse all seven messages and create no state. Native iPad execution and original VMM execution must be reported separately; local tests do not establish full macOS27 CPU/VMM operation.
