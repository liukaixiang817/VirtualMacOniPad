# Private VZ27 compact witness provider

The private router implements exactly the six compact witness symbols imported by the original macOS27 Virtualization image: destroy, initialize with copy, assign with copy, assign with take, inline buffer copy and enum tag. It dispatches only to three UUID-pinned, authenticated metadata/layout contracts: `CachingOptions`, `VZEFISignature`, and `VZVirtualMachineViewAdaptor`. Those are the three compact tables / 17 original witness bind sites observed in this image. This is not a general Swift compact interpreter.

The existing CachingOptions adapter is compiled under private helper names without editing its frozen source. EFI and ViewAdaptor already use private helper names. Only the six original entry points and a bounded metadata query are exported. Unknown metadata and overlapping storage trap before mutation. There is no global Swift interposer or compatibility handler registry. Swift and Objective-C ownership is performed by the UUID-checked genuine host primitives; no synthetic metadata or old Virtualization class is returned.

The ViewAdaptor's one owned ObjC field is a real `_VZVirtualMachineViewAdaptorInternal`, created by the genuine public initializer from a stopped Mac virtual machine. Its ownership test observes the internal object's weak deallocation. It does not mistake the field for a direct VZVirtualMachine reference. Creating the genuine fixture uses a private temporary EFI variable store, deleted when construction returns. It never starts or resumes the VM.

Actual native Mac tests of the combined provider are frozen at `DeviceDiagnostics/2026-10-08-full-macos27-cpu-vmm/virtualization27-native-closure-v2/cvw-router-fixtures-v1`: CachingOptions 80 lifecycle cases / 405 checks; EFI 250 / 2791; ViewAdaptor 40 / 204. All 370 cases / 3400 checks passed. The EFI fixture covers a certificate and actual Data empty, inline, one-reference, and two-reference shapes, with real custom owner deallocation counters where applicable. The enum getter is compared with the authenticated original witness. Six negative control executions for unsupported genuine Int and overlap trap as expected. The private iPad provider is built and strictly signed, but has not executed there yet.

`prepare-modern-vz-cvw-router.py` preserves all code, metadata and witness section bytes. It adds one strong app-private dependency with a new positive ordinal, then routes **only** the six matching chained-import rows and their six nlist rows to that provider with weak flags cleared. All unselected imports remain byte-identical. Existing PAC witness bind entries retain their original authenticated contracts and bind to these true entry points through dyld.

This explicitly introduces new positive provider semantics instead of pretending the reconstructed flat/weak closure was the original macOS closure. The library must be scoped to that VZ image; never use `DYLD_INSERT_LIBRARIES` or global Swift replacement. Other required imports still need their real providers. Continue the 844-name prerequisite gate / load-only probe until that closure is established; these witness results alone do not authorize configuration or guest execution on iPad.
