# 独立 macOS27 后端的后续实现

当前优先级是让已连接 iPad 上的原始 macOS27 Virtualization/VMM 使用自有 CPU 后端启动真实来宾，并显示可操作的来宾画面。仅有静态依赖闭合、探针通过或框架加载，不构成启动验收。

首次可见启动配置明确使用零网卡、零音频设备。这个配置只是开发阶段；真实网络、22222 端口 SSH 和完整来宾可用性仍属于当前任务，不因列出本清单而取消。

可以在主启动链验证后补齐的功能：

| 功能 | 当前受限行为 | 后续工作与验证 |
| --- | --- | --- |
| macOS 显示服务、亮度、HDR headroom 和外接显示色彩空间 | iPad 使用自己的显示路径；没有兼容实现的服务请求明确失败，不伪造 Apple 服务对象或成功值 | 根据实际来宾调用补充 UIKit/CoreGraphics 实现，验证画面、色彩和显示变化 |
| IOSurfaceAccelerator 的新来宾转换命令 | Mac27 的 432 字节请求与当前 iPad16 的 368 字节接口不一致；未证实的转换明确返回“不支持”，不提交未知驱动数据 | 对比真实字段布局和版本能力，再实现安全转换；验证实际来宾图形请求及错误回退 |
| 音频输入和输出 | 首次启动配置不创建音频设备 | 接入原 Virtualization 音频端点与 iPad 音频会话，验证持续播放、录音和路由变化 |
| 物理 USB 主机和设备转接 | 尚无独立、已验证的转接实现 | 只针对明确设备建立真实接口，验证连接、断开和清理 |
| SVE、SME、AMX、嵌套 EL2/VHE 和扩展 CPU 能力 | 自有 CPU 能力配置不宣告尚未实现的功能 | 真实保存/恢复和执行支持完成后再宣告，验证迁移、异常和多 CPU 一致性 |
| macOS 子进程动态沙箱配置 | 当前 iPad 的真实 `sandbox_apply` 测试返回 `-1 / ENOTSUP(45)`，配置未应用；主启动路线已使用明确声明的自有平台子进程准备入口，保留真实启动 owner、身份、签名和已授权权限检查 | 在支持动态配置的原生接口上实现或选择可验证的等效隔离；实际调用与拒绝见证均通过后，才声明沙箱配置已应用。当前结果不能证明 macOS27 配置格式兼容或不兼容 |
| 非必需插件安装与系统服务注册 | 缺少兼容实现的入口返回真实不可用错误 | 根据真实调用路径补充自有注册和生命周期，不冒充系统服务 |

启动前仍必须处理的工作包括：实际 CPU 状态访问和复位、计时器中断、最终签名运行包、真实父子进程身份与 IPC、磁盘启动、iPad 可见画面和输入。任何影响实际启动的上述延期项，应立即重新提升为阻塞修复。

当前沙箱阻塞的设备实测：[一次真实调用与返回值](/Users/liukaixiang/Documents/VirtualMacOniPad/DeviceDiagnostics/2026-10-08-full-macos27-cpu-vmm/native-sandbox-apply-compat-device-v6-arm64-execpolicy-attempt1/actual-execute/stdout)。控制器传输阶段返回 0 仅表示诊断记录已完成；探针实际状态为 72，沙箱未应用。自有平台子进程准备入口已实际运行；这不表示动态沙箱配置已应用。Runtime29/App40 的有界初始化已完成，但真实来宾启动仍失败。原生 VM 初始化观察器实际进入一次、未记录正常返回；尚未证明有异常，也尚未进入公开 CPU 创建。

截至 2026-10-14，Runtime30/App41 仅完成 HOST 打包，具体安装清单 V23 被自动审批拒绝，等待人类确认；尚未更新 iPad。Main19/QGA7 的持久 SSH 路线只完成 HOST 准备，尚未部署、启动来宾任务或验证 `lkx` 经 22222 实际登录。

基础键鼠输入仍须在可见来宾画面上验证。macOS NSEvent、rawHID 转接及扩展滚动、媒体键可以后补，但任何阻碍基础输入的部分须回到优先主线。CPU 状态/复位、计时器/GIC、RAM 映射及真实 vCPU 执行不属于延期项。

本轮真实崩溃已确认：Virtualization 子进程在虚拟 USB HCI 初始化期间 SIGSEGV（Child RVA 0x2449f4，空 self + 0x140）。当前 IOUSBHostControllerInterface 基类只实现“不可用”，genuine VMM 的 AVP USB device controller 描述符构造会调用它。该设备与标准 XHCI 键鼠路线不同，不能据此认定基本键鼠不可用。虚拟 USB 控制器及基本输入属于当前启动主线，不能按物理 USB 转接项目延期，也不能仅把失败 initializer 改成返回 self 就宣称完成。

随后已用 iPad 原生 `/usr/sbin/ioreg` 只读确认：当前 boot 没有发布 `AppleUSBUserHCIResources` 服务（查询正常结束、匹配树为空，未尝试打开 userclient）。直接迁移 Mac IOUSBHost 库不能证明能力存在。当前优先修复实际 AVP 控制器初始化，保留基本 USB 键鼠；仅当原消费路径证明适用时，才明确延后 USB 恢复/DFU 的外部连接能力。目前尚未证明真实可选配置门，也尚未部署替代控制器。
